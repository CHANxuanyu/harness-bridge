# 产品形态：以项目为中心的原生会话桌面工作台

_2026-10-07 方向调整，作者 Xuanyu CHAN。统一计划见 [PROJECT_PLAN.md](PROJECT_PLAN.md) §1–§9；
实际完成度以 STATUS 和验证矩阵为准。本文替代此前的 “跨 harness Advisor + Executor” 产品摘要，
旧形态保留在文末作为已实现能力与历史证据，不再是首版必经路径。_

**RepoBridge（仓库/包名仍为 harness-bridge / `hbridge`）是一个轻量的本地桌面工作台。
同时拥有多个 coding plan 的用户，在一个以项目为组织中心的窗口里，直接使用 Codex、Claude Code
等各家原生 CLI 会话。** 模型、工具执行和原生上下文仍由各家 CLI 负责；App 负责项目、会话、
进程、可见性、恢复和交接。

它不是继续扩展的 Advisor/Executor 多 agent 编排，也不是给原有任务调度后台套的 dashboard。

## 使用形态

```text
RepoBridge 窗口
 ├─ 项目 A（本地目录，通常是 Git repo）
 │    ├─ 会话 1 · Claude Code（原生交互 CLI，App 自有终端）  ← 当前写入会话
 │    ├─ 会话 2 · Codex（已结束，可原生恢复）
 │    └─ 交接记录：会话 1 → 会话 3（人工交接，非无损切换）
 └─ 项目 B …
每个会话旁边：真实终端 · 执行活动 · 权限请求 · 文件变更 · 失败原因 · 恢复状态
```

| 部分 | 职责 |
|---|---|
| 项目 | workspace 的组织中心：本地目录、Git 状态、所属会话、交接记录 |
| 会话 | 固定一种 harness 的原生 CLI 会话；绑定工作目录和观察到的原生会话 ID |
| 原生 CLI | 模型选择、对话、工具执行、权限判断、上下文与历史；使用用户已有的原生登录和计费 |
| App | 启动/停止/恢复进程，展示真实终端与旁路事件，执行单写入约束，生成交接说明 |

## 已确定的产品约束

- **项目是 workspace 的组织中心。** 会话、交接、文件变更都挂在项目下。
- **每个 session 固定一种 harness。** 不在一个会话内切换厂商。
- **换 harness = 同项目下新建会话并交接。** App 不把它伪装成同一个原生 session 的无损切换；
  新会话拿到的是交接说明和当前代码，而不是旧会话的私有上下文。
- **第一版允许人工交接。** 用户确认/编辑 App 生成的交接说明，新 agent 阅读代码和进度后继续。
- **同一实际工作目录默认只有一个由 App 管理的活动写入会话。** 第二个会话启动前被拒绝并说明原因。
- **用户在 App 内能看见** 真实对话、执行活动、权限请求、文件变更、失败原因、会话恢复状态。
  对话有两种视图（2026-10-08 加入，按会话切换并记住默认）：**终端**＝原生交互 CLI 本身，权限在终端中回答；
  **对话**＝基于原生结构化协议（Claude Code stream-json、Codex app-server）的图形界面，权限请求以卡片显示、
  由用户点击允许/拒绝。两种视图连接的是同一个原生会话；切换不换 harness、不发消息、不同时运行两个写入者。
  App 从不代为批准，也不把终端画面解析成聊天记录。
- **可在官方桌面客户端中继续**：同一会话可在 Claude Desktop（`claude --desktop --resume`）或 Codex App
  （`codex://threads/<id>`）中打开；打开前 RepoBridge 释放自己的连接，打开后在用户确认那边结束之前不再写入。
- **认证与计费只走各家允许的原生方式。** App 不读取、不收集、不保存登录令牌；不注入 API key；
  启动会话时不传递会把订阅悄悄切换成 API 付费的 API/provider 环境变量，并显示被拦下的变量名。
- **首版先做好 Codex 与 Claude Code。** ZCode 等其他 harness 后续按同一会话模型接入。

## 一次典型使用

1. 用户打开 RepoBridge，添加本地项目目录。App 显示 Claude Code / Codex 是否可用及版本。
2. 在项目里新建 Claude Code 会话。App 在自有终端中启动原生 `claude`，用户像平常一样对话；
   App 预分配并核对原生会话 ID，旁路记录工具活动、权限请求和停止事件，并显示工作目录的 Git 变更。
3. Claude 额度用尽或用户想换 Codex：停止当前会话，点击“交接到 Codex”。App 根据项目 Git 状态、
   会话活动和用户补充的进度说明生成交接说明；用户确认后，在同一项目新建 Codex 会话并发送这份说明。
4. 旧会话保留为历史，可在不与当前写入会话冲突时用原生 `--resume` / `codex resume` 恢复。
5. 关闭再打开 App：项目、会话、交接链和最后终端输出仍在；运行中被中断的会话显示为“已中断，可恢复”。
6. 想用图形界面：把会话切到“对话”，看到同一会话的历史并继续；想到官方桌面里接着做：在会话菜单里选
   “在 Claude Desktop / Codex 中打开”，回来时确认那边已结束，RepoBridge 用原生恢复接着同一会话。

## 首版工作默认

- 单用户、单机、本地目录；先以当前 macOS 环境交付，保留 Linux 离线回归。
- 会话进程归 App 所有：关闭 App 等同关闭终端，进程结束、原生会话由各家 CLI 保存，可在 App 中恢复。
  不在首版承诺关闭窗口后会话仍在后台运行。
- 默认工作目录为项目根目录；单写入约束按真实路径（realpath）判定，作用于同一 state 目录下的 App。
- 不自动发送模型消息：只有用户在终端输入，或用户确认“启动并发送交接说明”时，才会产生模型调用。
